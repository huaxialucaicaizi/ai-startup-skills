# 一人公司增长获客 / OPC Growth Playbook

帮一人公司在**小红书、抖音、视频号**做冷启动：从定位出发，搭增长漏斗、排增长实验、出内容日历和口播脚本，每周按真实数据复盘。

本 skill 不讲通用增长理论，只做五件事：定位确认、漏斗与指标、实验池、内容日历与脚本、周复盘。

## 输入

缺什么就问什么；无法追问时标"待补充"继续：
- 产品 / 服务一句话、目标用户、核心卖点（有验证结论更好，例如"给谁 / 解决什么 / 卖点 / 付多少钱"）
- 想做的平台：小红书 / 抖音 / 视频号（可多选）
- 现有账号情况：是否已有账号、已有内容和数据（只用用户提供的数据）
- 每周可投入的时间、能否出镜、能否投流及预算
- 转化路径：私信 / 加微信 / 落地页 / 店铺 / 小程序

## 工作流

### 1. 定位确认
用 `references/positioning-check.md`：一句话定位、目标用户画像、3 个内容支柱、账号人设。和 BP、验证结论中的定位保持一致；有冲突时指出并请用户选。

### 2. 漏斗与指标
用 `references/growth-funnel.md`：曝光 → 互动 → 关注 / 留资 → 咨询 → 付费 → 复购 / 转介绍，每层写清指标定义和数据来源（平台后台、表格记录）。
- 没有历史数据时，目标一律写"首周跑基线，第二周起按自己的数据设目标"。
- **不提供"行业平均"互动率、转化率。**

### 3. 增长实验池
用 `references/experiment-pool.md`：把想法写成"假设 → 做法 → 指标 → 判断标准 → 周期"，用 ICE（影响 / 信心 / 容易度，各 1–5 分，用户自评）排序，每周最多同时跑 2–3 个（建议值，可自行调整）。用户不在场、无法自评时，给出"建议分 + 理由"并标"待用户确认"。
- 样本很小（例如单条内容）时，结论只能是"继续观察"或"调整"，不要据此宣布实验成功。

### 4. 内容日历与口播脚本
- `references/content-calendar.md`：按内容支柱排 2–4 周日历，标平台、形式（图文 / 短视频 / 直播）、选题、目标指标、行动引导。
- `references/video-script.md`：口播结构"开头钩子 → 痛点场景 → 方案演示 → 证据 → 行动引导"，证据只用真实案例或数据，没有就写"待补充"。
- 同一选题可按平台改写，平台规则以各平台官方规则为准。

### 5. 合规检查
用 `references/compliance.md` 逐项检查：广告标识、不虚假宣传、AI 生成内容标识、未上线产品如实说明。

### 6. 周复盘
用 `templates/weekly-review.md`：记录各层真实数据、实验结论（继续 / 调整 / 停止）、下周计划。没有数据的格子写"未记录"，不估算。

最终按 `templates/growth-plan.md` 输出。

## 可选衔接（不依赖其他 skill）

- 有想法验证结论时，直接用其中胜出的卖点和目标人群。
- 有 BP 时，读取定位与目标客户，保持口径一致；增长数据可回填 BP 的"进展"（标注"实际数据"及统计时间）。
- 成交环节的定价、报价、私域成交可配合第 6 步定价与成交：[opc-pricing-sales](https://github.com/huaxialucaicaizi/opc-pricing-sales)。

## 硬性规则

- 不编造粉丝数、播放量、互动率、转化率和"行业基准"；用户没提供的写"待补充"。
- 阈值和频率没有出处的，标"建议值，可自行调整"。
- 不教刷量、买粉、搬运他人内容、虚假测评。
- 推广内容按 `references/compliance.md` 标识；平台规则以各平台官方规则为准，本 skill 不复述未核实的平台规则。
- 本 skill 不构成法律意见。
