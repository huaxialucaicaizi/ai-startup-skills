# AI 产品 MVP 验证 / AI MVP Validation

面向 **AI 工具、AI 应用、Agent** 类产品。在写 BP、申请政策或找投资**之前**，用"调研 + Meta 广告投放验证"把想法验证一遍，并把过程留成评委和投资人看得懂的证据。

本 skill 不讲通用创业方法论（选利基、价值主张画布、商业模式画布等），只做五件事：调研、痛点与 AI 产品判断、一人能否做、广告投放验证、结论（可选衔接写 BP）。

## 输入

- 想法一句话：为谁、解决什么问题、用什么 AI 能力解决
- 目标市场：海外 / 国内（决定用 Meta 还是国内平台）
- 依赖的模型或 API（如已确定）、预计每次调用的成本（用户有就写，没有标"待补充"）
- 创始人情况：每周可投入时间、可投入资金（含广告预算）、技能、会用的 AI 工具
- 已有证据（如有）：访谈记录、等待名单、付费意向（注明来源）
- 目标：申请政策 / 园区 / 大赛 / 投资

缺的项标"待补充"继续往下做，不要替用户猜。

## 工作流

### 1. 调研：桌面调研 + 用户访谈
按 `references/desk-research.md` 做竞品、搜索热度、社区讨论三项桌面调研，再用 `references/interview-guide.md` 访谈目标用户。桌面调研只记录查到的真实信息并附来源链接；查不到写"未查到"，不要推测。

### 2. 痛点真伪 + AI 产品特有判断
按 `references/pain-and-feasibility.md`：
- 痛点三问：谁痛、现在怎么解决、愿不愿付费（标证据状态：`已验证（有记录）` / `用户自述、未验证` / `待验证`）。用户说"聊过几个人"但没有记录的，算"用户自述、未验证"，不计入达标人数。
- AI 产品三项判断：**会不会被大模型原生功能覆盖**、**模型 / 推理成本对单位成本的影响**、**数据与合规**（生成式 AI 备案、内容标识等，只引用该文件中已核实的官方链接）。

### 3. 一人能否做
时间、钱（含广告预算和模型调用费）、技能、AI 工具四方面，列出需要外包或合作的环节和关键人风险。

### 4. 核心方法：Meta 广告投放验证
按 `references/meta-ads-validation.md`：落地页 / 等待名单 + 小预算 Facebook / Instagram 广告，多版本卖点和受众 A/B 测试，记录 CTR、CPC、落地页转化率、单线索成本、预付 / 付费意向，并对照判断标准。
- Meta 主要适用于**出海 / 海外用户**；国内用户换成小红书聚光、巨量引擎等平台，思路相同。
- 所有阈值标"建议值，可自行调整"；**不编造行业基准数据**。
- 未上线产品必须如实说明是"等待名单 / 内测预约"。

辅助方法（`references/validation-methods.md`）：小红书笔记测反应、预售、人工模拟交付。

### 5. 记录与结论
用 `references/validation-log.md` 只记录真实发生的数据。下结论前先写两样东西：

**① 组合公式**：把验证对象写成一个组合，而不是笼统的"想法"：

> 给谁（人群）/ 解决什么（痛点场景）/ 用哪个卖点 / 付多少钱（价格或付费方式）

- 卖点和人群填广告测试中**胜出的版本**（落地页转化率、单线索成本最好且数据足够的那一版）；没有胜出版本时写"未分出"
- 每一格标证据状态：已验证 / 用户自述 / 待补充。价格没有实际付费支持时标"待验证"

**② 固定结论句式**：

> 已验证的是 ___（附证据），下一步要验证的是 ___（附方法和判断标准）。

然后给出三种结论之一：
- **继续**：可输出 BP 素材包（见"可选衔接"）
- **调整**：说明改什么（人群 / 卖点 / 方案 / 定价 / 渠道），可以是"补做某项验证"
- **放弃**：说明原因，保留记录

结论必须对照判断标准写依据。证据不足（样本或预算没跑够、标准未达到）时只能是"调整"；AI 产品三项判断中任一项为"高风险且无应对"（包括未评估）时，不能是"继续"。

## 面向政策申报 / 投资时的证据整理

- 申请政策或园区：把访谈记录、广告测试报表截图、等待名单数量整理成"市场验证证据"附件；写清测试时间、预算、样本量，只写实际数据。
- 找投资：重点突出付费 / 预付意向和单线索成本，其次是转化率和访谈。
- 合规进展（备案、标识）如实写"已完成 / 进行中 / 未开始"。

## 可选衔接（不依赖其他 skill）

本 skill 可单独使用。结论为"继续"时，可输出 **BP 素材包**；如需写 BP，可选用 [business-plan-skill](https://github.com/huaxialucaicaizi/business-plan-skill) 或任何 BP 工具：

| 验证产出 | 用在 BP / 申报材料的哪里 |
|---|---|
| 组合公式（给谁 / 解决什么 / 卖点 / 付多少钱） | 执行摘要、定位、商业模式（按证据状态写，"待验证"不写成"已验证"） |
| 固定结论句式 | 进展、下一阶段计划；路演中的"验证进度"页 |
| 谁痛、场景、访谈摘录 | 痛点与用户 |
| 竞品与大模型原生功能对比 | 竞品分析、差异化 |
| 广告测试数据、等待名单、预付 | 进展、市场验证（标"实际数据"） |
| 单位成本（含模型调用） | 商业模式、财务假设 |
| 合规判断与进展 | 合规与风险 |
| 一人可行性、AI 工具分工 | 团队 |

结论为"调整"时，组合公式和结论句式同样可用于路演的"验证进度"说明。"仍缺的证据"可作为评委或投资人可能追问的问题清单。

## 硬性规则

- 不编造市场规模、搜索热度、用户反馈、广告数据、行业基准。用户没提供的写"待补充"。
- 判断标准中的阈值没有出处的，标"建议值，可自行调整"。
- 法规、平台规则只引用 references 中已核实的官方链接；没收录的写"请以官方最新规定为准"，不要凭印象概括条款。
- 广告不得虚假宣传，未上线产品如实说明是等待名单。
- 本 skill 不构成法律意见；合规问题建议咨询专业人士或主管部门。
