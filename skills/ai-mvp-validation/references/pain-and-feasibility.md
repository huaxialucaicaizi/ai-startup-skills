# 痛点真伪、AI 产品判断与一人可行性检查

## 第一部分：痛点真伪

### 1. 谁痛
- 具体人群：职业 / 行业 / 公司规模 / 角色（例："10 人以下外贸公司的业务员"，不是"中小企业"）
- 具体场景：在什么时候、做什么事时遇到问题
- 频率：每天 / 每周 / 偶尔（只写用户访谈或观察到的，未知写"待验证"）
- 痛的后果：浪费时间、出错、丢客户、多花钱（有数据就写来源，没有写"待验证"）

### 2. 现在怎么解决
- 现有替代方案：人工、Excel、通用 AI、竞品、外包、干脆不解决
- 不满意的地方：贵、慢、麻烦、不准
- 判断：如果用户"不解决也能过"，痛点可能不够强

### 3. 愿不愿付费
行为证据强弱（从强到弱）：
1. 已付款 / 预付定金
2. 签了试用或采购意向
3. 愿意留联系方式、加群等上线通知
4. 口头说"有需要会买"（最弱，不能单独作为付费证据）

### 自查
- [ ] 每个结论都有证据，并标了证据状态
- [ ] 没有把"我觉得"写成"用户认为"
- [ ] 至少找到 1 种现有替代方案

## 第二部分：AI 产品特有判断

每项给出风险等级（低 / 中 / 高）、依据和应对。依据只写查到的事实或用户提供的数据，未知写"待补充"。

### A. 会不会被大模型原生功能覆盖
- 直接用主流通用 AI 产品（聊天、文档、插件等），能否做到同样的事？亲自试一遍并记录结果（截图）
- 你的产品比"直接用通用 AI"多了什么：专有数据、工作流集成、行业知识、交付结果而不只是回答、合规保障等
- 判断：如果只是"套一层提示词"、通用产品已经能做到，风险为**高**
- **没做这项对比（未评估）时，按"高风险且无应对"处理**

### B. 模型 / 推理成本对单位成本的影响
- 估算一次典型任务的模型调用成本：调用次数 × 单次 token 量 × 单价（单价以模型服务商官方价格页为准，注明查询日期）
- 单位成本 = 模型调用成本 + 其他成本（服务器、支付手续费等）
- 对比计划售价：模型成本占售价比例越高，风险越高；比例的可接受范围由用户自行设定（建议值，可自行调整）
- 用户没有成本数据时写"待补充"，不要编单价

### C. 数据与合规
- 数据来源：用户上传、公开数据、第三方数据？是否涉及个人信息、版权内容？
- 面向中国境内公众提供生成式 AI 服务时，需关注《生成式人工智能服务管理暂行办法》（2023-08-15 起施行），其中第十七条规定：提供具有舆论属性或者社会动员能力的生成式人工智能服务的，应当按照国家有关规定开展安全评估，并履行算法备案等手续。原文：https://www.cac.gov.cn/2023-07/13/c_1690898327029107.htm
- AI 生成合成内容的标识要求见《人工智能生成合成内容标识办法》（2025-09-01 起施行），发布说明：https://www.cac.gov.cn/2025-03/14/c_1743654685899683.htm
- 出海产品：遵守目标市场的数据与 AI 相关法规（本 skill 未收录，以当地官方规定为准）
- 是否需要备案、具体怎么做，以主管部门最新规定为准，必要时咨询专业人士

## 第三部分：一个人能不能做

| 方面 | 要回答的问题 |
|---|---|
| 时间 | 每周能投入多少小时？验证期和上线后分别需要多少？ |
| 钱 | 验证阶段需要多少钱（广告预算、模型调用、工具）？能承受的最大投入？ |
| 技能 | 产品、内容、销售、交付中，哪些自己会？哪些不会？ |
| AI 工具 | 哪些环节可以用 AI 工具完成（写代码、做图、写文案、客服）？用的是哪些工具？ |

### 输出
- 一个人能做的环节
- 需要外包 / 合作的环节（写清谁、多少钱，未知写"待补充"）
- 关键人风险：创始人时间不够或生病时怎么办

> 这部分结论会直接用在 BP 的"团队"章节和路演的"你一个人怎么交付"问答。
