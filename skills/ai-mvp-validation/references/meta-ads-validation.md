# 核心方法：Meta 广告投放验证

用"落地页 / 等待名单 + 小预算 Facebook / Instagram 广告"，在产品做完之前测试：**有没有人点、点了愿不愿留资、愿不愿预付**。

> **适用范围**：Meta（Facebook / Instagram）主要适用于**出海 / 海外用户**。面向国内用户时，换成国内平台，例如 [小红书聚光](https://ad.xiaohongshu.com/)、[巨量引擎](https://www.oceanengine.com/)，思路相同（落地页 / 表单 + 多版本卖点 A/B + 相同指标）。各平台的具体投放规则以平台官方说明为准。
>
> **数字说明**：本文所有预算、周期、阈值都**没有统一出处**，是**建议值，可自行调整**。本 skill **不提供行业基准数据**（如"行业平均 CTR"），用户如有来源可靠的基准，可替换并注明来源。

## 步骤

### 1. 准备落地页 / 等待名单
- 一页讲清：给谁用、解决什么、核心卖点、（可选）价格区间
- 行动按钮：加入等待名单 / 预约内测 / 预付定金（三选一或组合）
- **如实说明产品状态**：未上线写"正在开发，加入等待名单获取内测资格"，不要写成已上线
- 装好统计（访问、留资、预付），能导出数据或截图

### 2. 设计 A/B 版本
- 卖点版本：2–3 个（例：省时间 / 提高质量 / 降低成本），每个版本只改一个变量
- 受众版本：2–3 组（按职业、兴趣、地区等平台提供的选项）
- 组合不宜太多，否则每组预算太少、数据不够判断

### 3. 设定预算与周期（建议值，可自行调整）
- 每个版本给到能产生一定点击量的预算再判断，避免一两天就下结论
- 建议总周期 7–14 天；总预算按自己能承受的范围定，并在开始前写下来
- 设止损线：某版本花到预定金额仍几乎没有点击，就暂停

### 4. 投放与记录
- 每天记录每个版本：花费、展示、点击、落地页访问、留资、预付
- 数据以广告后台和落地页统计为准，截图留证

### 5. 计算指标
| 指标 | 计算方式 | 说明 |
|---|---|---|
| CTR 点击率 | 点击 ÷ 展示 | 卖点和素材吸不吸引人 |
| CPC 单次点击成本 | 花费 ÷ 点击 | 获取注意力的成本 |
| 落地页转化率 | 留资 ÷ 落地页访问 | 看完说明后是否真的感兴趣 |
| 单线索成本 | 花费 ÷ 留资 | 获取一个潜在用户的成本 |
| 付费意向（表单） | 留资中勾选"愿意付费"的人数 | 只是意向，不等于付费 |
| 实际预付 | 真实完成预付的人数（不含亲友） | 最强信号 |

注意：广告后台的"点击"和落地页统计的"访问"常常不一致，两个都记录，计算落地页转化率时用落地页统计的访问数。

### 6. 判断标准（全部为建议值，可自行调整）
不用行业平均值做标准，而是用**自己的商业模式倒推**：
- **单线索成本**：设定一个你能接受的上限，例如"预计客单价 × 预计线索到付费转化率"的一定比例；结果低于上限 → 正向信号。**售价或转化率未定时，上限无法计算，这一项写"无法判断"，不要套用别人的数字**
- **落地页转化率**：建议值 5% 以上视为卖点被认可（可自行调整）
- **实际预付**：建议值至少 3 位真实预付（不含亲友）。表单里的"愿意付费"只算意向，不能替代实际预付
- **版本对比**：某个卖点或受众明显好于其他版本 → 说明方向，下一轮集中测试
- **数据不足**：总点击或访问太少（例如访问少于 100，建议值）时，不下结论，先补预算或改素材
- CTR、CPC 主要用来**比较版本**，不单独作为"继续 / 放弃"的依据

## 合规提示

- 不虚假宣传：不承诺做不到的效果，不使用虚构的用户评价或数据
- 未上线产品如实说明是等待名单 / 内测预约
- 广告内容与落地页内容一致。Meta 广告规则要求广告推广的产品和服务与落地页上推广的一致，详见 [Meta Advertising Standards](https://transparency.meta.com/policies/ad-standards/)（规则会更新，以官方最新版本为准）
- 收集个人信息（邮箱、电话）时说明用途，遵守目标市场的隐私法规
- 预付需写明交付时间和退款规则

## 输出
- 每个版本一行的结果表（见 SKILL.md 输出模板）
- 对照判断标准的结论
- 最好的卖点 / 受众组合，作为 BP 和路演中的"目标用户与卖点"依据
